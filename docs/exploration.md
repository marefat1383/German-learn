## ۲. ماژول واژگان

### مقیاس واژگان پیشنهادی (CEFR)

| سطح | واژگان فعال | واژگان شناختی | منطق |
|-----|------------|--------------|------|
| A1  | 500-800    | 1,000        | پایه ارتباطی |
| A2  | 1,000-1,500| 2,000        | موقعیت‌های روزمره |
| B1  | 2,000-2,500| 4,000        | موضوعات آشنا |
| B2  | 3,500-4,500| 8,000        | موضوعات انتزاعی |
| C1  | 6,000-8,000| 12,000       | متون پیچیده |
| C2  | 10,000+    | 16,000+      | تسلط بومی‌گونه |

> **تصمیم باز**: این اعداد از تحقیقات CEFR استخراج شده‌اند اما باید با تحقیق کاربری تأیید شوند. معماری باید بدون تغییر کد با هر عدد کار کند.

### سیستم تکرار فاصله‌ای (SRS)

الگوریتم پیشنهادی: **SM-2** (پایه Anki) با تنظیمات:

```
فاصله بعدی = فاصله فعلی × EaseFactor
EaseFactor (پیش‌فرض 2.5) بر اساس کیفیت پاسخ تنظیم می‌شود:
  - پاسخ عالی (5): EF += 0.1
  - پاسخ خوب (4): بدون تغییر
  - پاسخ ضعیف (3): EF -= 0.14
  - فراموشی (0-2): بازنشانی به روز اول
```

**تعارض**: SM-2 برای واژگان تکی طراحی شده. برای جملات نمونه و زمینه‌ها باید تطبیق یابد.

### ساختار داده واژه

```python
# مدل مفهومی — نه کد نهایی
VocabItem:
  word: str                    # واژه آلمانی
  translation_fa: str          # ترجمه فارسی
  level: CEFRLevel
  examples: List[Example]      # ۳-۵ جمله با ترجمه
  pronunciation_ipa: str
  audio_url: str | None        # آنلاین یا کش محلی
  
SRSCard:
  vocab_id: UUID
  user_id: UUID | None         # None = بدون حساب
  ease_factor: float
  interval_days: int
  next_review: datetime
  review_history: List[ReviewEvent]
```

## ۳. ماژول محاوره ۱۵ دقیقه‌ای

### مقیاس‌بندی سناریو در سطوح مختلف

| سطح | پیچیدگی سناریو | واژگان هدف | ساختار دستوری |
|-----|---------------|-----------|--------------|
| A1  | رستوران: سفارش ساده | اسامی، اعداد، رنگ‌ها | جملات حال ساده |
| A2  | فروشگاه: خرید و قیمت | صفات، ضمایر | گذشته ساده، سؤال |
| B1  | دفتر: مصاحبه کاری | اصطلاحات حرفه‌ای | زمان‌های مختلف |
| B2  | بحث: موضوع اجتماعی | واژگان انتزاعی | جملات مرکب |
| C1  | مذاکره: قرارداد | اصطلاحات تخصصی | ساختارهای پیچیده |
| C2  | مناظره: موضوع فلسفی | واژگان ادبی | تمام ساختارها |

### جریان محاوره طولانی‌مدت

```
شروع سناریو
     │
     ▼
AI نقش شخصیت را بازی می‌کند
(مثال: گارسون رستوران)
     │
     ▼
کاربر صحبت می‌کند (STT)
     │
     ├─── خطای تلفظ ──→ بازخورد فوری + ادامه
     │
     ├─── خطای دستوری ──→ اصلاح توضیحی + ادامه
     │
     └─── پاسخ صحیح ──→ AI پیش می‌رود
          │
          ▼
     نقطه توقف احتمالی
     (ذخیره وضعیت کامل)
          │
          ▼
     پایان ۱۵ دقیقه یا تکمیل سناریو
```

**تعارض کلیدی**: محاوره طولانی‌مدت نیاز به حافظه زمینه‌ای دارد. هر LLM محدودیت context window دارد. برای ۱۵ دقیقه محاوره، باید استراتژی خلاصه‌سازی یا sliding window داشته باشیم.

### ماندگاری جلسه محاوره

```python

  scenario_type: str
  scenario_context: dict       # وضعیت کامل سناریو
```

## ۵. موتور سختی تطبیقی

### معیارهای چندگانه

```
امتیاز_تسلط = (دقت × ۰.۵) + (سرعت_نرمال × ۰.۳) + (تلاش_اول × ۰.۲)

دقت = پاسخ‌های صحیح / کل پاسخ‌ها
سرعت_نرمال = min(زمان_هدف / زمان_واقعی, 1.0)
تلاش_اول = ۱ اگر بار اول صحیح، ۰.۵ اگر بار دوم، ۰ اگر بیشتر
```

> **تصمیم باز**: وزن‌های ۰.۵/۰.۳/۰.۲ فرضی هستند. باید با داده کاربری کالیبره شوند.

### آستانه‌های انتقال

```
امتیاز > 0.85 برای ۵ تمرین متوالی → افزایش سختی
امتیاز < 0.50 برای ۳ تمرین متوالی → کاهش سختی
```

**تعارض**: آستانه‌های ثابت ممکن است برای کاربران مختلف مناسب نباشند. باید بین سادگی پیاده‌سازی و شخصی‌سازی تعادل برقرار کرد.

## ۶. نقاط یکپارچگی AI

### چه چیزی نیاز به AI دارد

| وظیفه | نیاز به AI | جایگزین |
|-------|-----------|---------|
| جملات نمونه واژه | بله — تنوع زمینه | الگو + جایگزینی |
| سناریوی محاوره | بله — پویایی | الگوهای پیش‌ساخته |
| بازخورد دستوری | بله — توضیح | قوانین ثابت برای خطاهای رایج |
| ارزیابی تلفظ | بله — STT | — |
| سؤالات دستور زبان | نیمه — تنوع | الگو + پارامتر |
| ترجمه واژه | خیر | دیکشنری ثابت |
| راهنمای IPA | خیر | دیتابیس ثابت |

### لایه مستقل از ارائه‌دهنده

```python
# رابط انتزاعی — پیاده‌سازی برای هر ارائه‌دهنده جداست
class AIProvider(ABC):
    async def generate_examples(self, word: str, level: str, count: int) -> List[str]: ...
    async def evaluate_speech(self, audio: bytes, expected: str) -> SpeechResult: ...
    async def generate_dialogue_response(self, context: DialogueContext) -> str: ...
    async def explain_grammar_error(self, error: GrammarError) -> str: ...
    async def generate_grammar_question(self, level: str, vocab: List[str]) -> Question: ...
```

### نقاط فراخوانی API

```
Desktop App                    FastAPI Backend              AI Provider
     │                               │                           │
     │── GET /vocab/next ──────────→ │                           │
     │                               │── generate_examples() ──→ │
     │                               │←── examples ─────────────│
     │←── vocab + examples ─────────│                           │
     │                               │                           │
     │── POST /dialogue/respond ───→ │                           │
     │   {audio: bytes}              │── evaluate_speech() ────→ │
     │                               │── generate_response() ──→ │
     │←── {feedback, next_turn} ────│                           │
```

**تعارض تأخیر**: بازخورد بلادرنگ محاوره نیاز به < 2 ثانیه دارد. فراخوانی‌های متوالی STT + LLM ممکن است این را نقض کنند. راه‌حل‌های احتمالی: streaming، پردازش موازی، یا کش پیش‌بینی‌شده.

## ۷. مدل اتصال (آنلاین/آفلاین)

### تقسیم‌بندی قابلیت‌ها

| قابلیت | آفلاین | آنلاین | یادداشت |
|--------|--------|--------|---------|
| مرور واژگان کش‌شده | ✓ | ✓ | نیاز به دانلود اولیه |
| تمرین دستور زبان (الگویی) | ✓ | ✓ | بدون AI |
| تمرین دستور زبان (AI) | ✗ | ✓ | |
| محاوره | ✗ | ✓ | STT + LLM |
| بازخورد تلفظ | ✗ | ✓ | |
| هماهنگ‌سازی پیشرفت | ✗ | ✓ | |
| SRS scheduling | ✓ | ✓ | محاسبه محلی |

### استراتژی هماهنگ‌سازی

```
آفلاین: تمام تغییرات در صف محلی ذخیره می‌شوند
         با timestamp و device_id

اتصال مجدد:
  1. ارسال صف محلی به سرور
  2. دریافت تغییرات سرور
  3. رفع تعارض: آخرین timestamp برنده است
     (استثنا: اگر هر دو طرف پیشرفت دارند، ادغام می‌شود)
```

**تعارض**: "آخرین timestamp برنده" ممکن است پیشرفت را از دست بدهد. مثال: کاربر روی دستگاه A واژه را یاد گرفته، روی دستگاه B فراموش کرده — کدام وضعیت صحیح است؟ پیشنهاد: در صورت تعارض، وضعیت "یادگرفته‌شده" حفظ شود (محافظه‌کارانه).

## ۱۱. سؤالات باز و تعارضات

### تصمیمات وابسته به ارائه‌دهنده AI
- کدام STT برای تلفظ آلمانی دقیق‌تر است؟ (Google vs Azure vs Whisper)
- آیا یک LLM برای همه وظایف کافی است یا باید تخصصی شود؟
- هزینه per-request در مقابل هزینه ماهانه — کدام مدل قیمت‌گذاری مناسب‌تر است؟

### تحقیق کاربری ناتمام
- تعداد بهینه واژگان برای هر سطح (اعداد جدول بخش ۲ فرضی هستند)
- آستانه‌های تنوع محتوا: کاربران چند بار تکرار را قبل از خستگی تحمل می‌کنند؟
- مدت زمان ایده‌آل جلسه برای هر ماژول

### تنش‌های معماری

| تنش | طرف A | طرف B |
|-----|-------|-------|
| آفلاین vs پیچیدگی | قابلیت آفلاین بیشتر | پیچیدگی هماهنگ‌سازی کمتر |
| تنوع محتوا vs هزینه API | محتوای تازه هر جلسه | هزینه و تأخیر کمتر |
| بازخورد فوری vs دقت | < 2 ثانیه پاسخ | ارزیابی دقیق‌تر |
| ماندگاری جلسه vs پیچیدگی | ادامه از هر نقطه | پیچیدگی state management |
| حساب اختیاری vs هماهنگ‌سازی | UX ساده‌تر | داده پراکنده |

### چارچوب رومیزی (تصمیم باز)

| گزینه | مزیت | معایب |
|-------|------|-------|
| Electron | وب‌تکنولوژی، RTL آسان | حجم زیاد، RAM بالا |
| Tauri | سبک، Rust backend | اکوسیستم کوچک‌تر |
| PyQt/PySide | Python native، یکپارچگی آسان با FastAPI | UI قدیمی‌تر |
| Flutter Desktop | RTL خوب، cross-platform | Dart، اکوسیستم جدید |

## ۱۲. فرض‌های کلیدی (باید تأیید شوند)

1. **FastAPI به عنوان واسط AI**: همه فراخوانی‌های AI از طریق بکاند می‌روند، نه مستقیم از Desktop
2. **SQLite محلی**: برای ذخیره‌سازی آفلاین کافی است
3. **یک کاربر per نصب**: نیازی به multi-user محلی نیست
4. **اینترنت برای محاوره الزامی**: STT آفلاین در scope نیست
5. **معلم انسانی اختیاری است**: برنامه بدون معلم کامل کار می‌کند
